# Email Assistant – Feature Overview

This document describes the Email Assistant feature that generates client-ready submission emails from job descriptions and resumes.

## 1. What the Email Assistant Does

- Generates a **subject line**, **email body (text + HTML)**, and optional **candidate table** for client submissions.
- Works in two modes:
  - From **existing candidates** (DB-backed flow).
  - From **uploaded resumes + JD** (standalone upload flow).
- Supports optional fields:
  - Rate card
  - Notice period
  - Location
  - Detailed vs. short candidate summaries
  - Custom prompt instructions
- Appends the HR signature once at the end of the email body, avoiding duplicates.

## 2. How to Access the Email Assistant

- Log in to KloudifyHR.
- Use the **unified KloudifyHR navbar** at the top.
- Click **Email Assistant**.
- The page is split into two panels:
  - **Left**: Inputs (client name, JD text/file, resumes, signature, options).
  - **Right**: Generated subject, email body preview, and optional candidate table.

## 3. Environment & Dependencies

The feature depends on:

- **Gemini API**
  - Env var: `GEMINI_API_KEY` (or `settings.gemini_api_key`).
  - Model: `gemini-2.5-flash-lite`.
- **Redis**
  - Env var: `REDIS_URL`.
  - Used by:
    - `RedisLLMUsageTracker` (LLM usage & quota tracking).
    - `EmailDraftCacheRedis` (caching recent drafts per user + client + requirement).

If these are not configured, the Email Assistant APIs will fail early with clear error messages in logs.

## 4. Redis Draft Caching

- Service: `services.email_draft_cache_redis.EmailDraftCacheRedis`.
- Keys are scoped per **user**, **client**, and **requirement/job**:
  - Pattern: `email_draft:{user_id}:{client_slug}:{requirement_slug}`.
- TTL: ~12 hours (configurable in the cache class).
- Caching happens automatically after a draft is generated by:
  - `POST /api/v1/email-drafts` (DB-based flow).
  - `POST /api/v1/email-drafts/from-uploads` (upload-based flow).
- Retrieval endpoint:
  - `GET /api/v1/email-drafts/recent` with query params:
    - `client_name`
    - Optional `requirement_title`
    - Optional `job_code`
- This is intended for future "Reopen last draft" UX so HR can avoid re-running the full LLM flow if nothing changed.

## 5. Basic Flow (Upload-Based)

1. HR navigates to **Email Assistant**.
2. Fills in:
   - Client name (required).
   - Requirement title / Job code (optional).
   - JD text and/or JD file.
   - One or more resume files.
   - Optional rate card, notice period, location.
   - Optional signature and prompt instructions.
3. Clicks **Generate Email Draft**.
4. The UI shows **multi-step loading messages** in the status text:
   - Uploading files
   - Extracting text
   - Generating email
5. On success, the right panel displays:
   - Suggested subject in an input (for easy copy/edit).
   - Email body preview (HTML).
   - Candidate table (if generated).
6. HR uses the copy buttons to paste content into their email client.

## 6. Authentication & Security

- All Email Assistant APIs require an authenticated user.
- The upload-based endpoint uses session-based auth via `get_current_user_or_redirect`.
- Draft caching is keyed by the current user's ID so drafts are not shared across HR users.

## 7. Current Limitations

- Only Gemini is supported as the LLM provider.
- Export to `.eml` / `.html` is **not** implemented yet (planned as a future enhancement).
- UI does not yet expose a "Reopen last draft" button, although the backend supports it via Redis.

## 8. Minimal Testing Approach

- Unit tests for:
  - Prompt builder summary style (short vs detailed).
  - Signature injection and de-duplication.
- API tests for:
  - Validation (missing request body).
  - Auth requirement for upload-based endpoint.
- Manual smoke tests:
  - Generate draft with 1 and multiple candidates.
  - Toggle detailed summaries on/off.
  - Provide/omit optional fields (rate card, notice period, location).
  - Verify signature appears once in both text and HTML previews.
